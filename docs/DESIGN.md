## 0. 目的

Claude Code（CLI・Claude Desktop の Code タブ）に仕事を頼んだとき、**「あとどのくらい待てばよいか」が分かること**。これが満たせれば十分。
バー・罫線の木・段階ごとの時間は、その数字を信じられるようにするための裏付けとして出す。

したがって、どの表示にも **残り全体の時間と終わる時刻**（`残り全体 約26分（15:12）`）を必ず出す。
待っても進まない状態（Claude が応答を終えて指示待ち・回答待ち）は、残り時間の代わりにそれをはっきり出す。

---

## 1. 方針

- **分母は手順。重みは時間。** 作業の初めに Claude が「段階 › 手順」の木と、手順ごとの見込み時間（分）を宣言する。
- **見込みは外れる前提で補正する。** 過去の実績（見込みに対して実際は何倍かかったか）で残り時間を補正する。
- **全体が増えたら必ず言う。** 手順の追加・見込みの見直しには理由を 1 行添える。
- **待っても進まないときは、残り時間を出さない。** 「指示待ち」「回答待ち」を出す。

## 2. 出す場面

| 場面 | 出すか |
|---|---|
| 3 手順以上になる依頼 | 出す |
| 短い質問・1〜2 手順で終わる依頼 | 出さない |
| 単位 | セッションごとに 1 本（サブエージェントや cmux の担当の分は親にまとめない） |

## 3. マスの意味

バーは █（済み）・▓（いまの手順。色で状態）・░（まだ）。手順の行の印:

| 印 | 意味 |
|---|---|
| 🟩 | 終わった |
| 🟨 | いまやっている（1 つだけ） |
| ⬜ | まだ |
| 🟦 | 回答待ち（時間の計測を止める） |
| 🟥 | 停止中（失敗など） |
| ⬛ | 中止（全体から外す） |

- 全体のバーは 10 マス、段階のバーは 5 マス。どちらも時間で重み付けした割合を丸める。
- 手順の行はマス 1 つ（状態）だけを出す。

## 4. 表示

### 4.1 1 行（ステータスライン・返信の先頭）— 最もよく見る表示

```
████▓░░░░░ 3/7 ｜ 今: 2.2 設計書を書く（経過7分・残り約4分） ｜ 残り全体 約26分（15:12）
```

| 状態 | 表示 |
|---|---|
| 作業中 | `████▓░░░░░ 3/7 ｜ 今: 2.2 設計書を書く（経過7分・残り約4分） ｜ 残り全体 約26分（15:12）` |
| 見込み超え | `████▓░░░░░ 3/7 ｜ 今: 2.2 設計書を書く（経過13分・見込み10分を超過） ｜ 残り全体 約25分（15:14）` |
| 回答待ち | `████▓░░░░░ 3/7 ｜ 🙋 回答待ち: 公開してよいですか？ ｜ 再開後 残り約26分` |
| 指示待ち | `████▓░░░░░ 3/7 ｜ 💤 次の指示待ち ｜ 再開後 残り約26分` |
| 停止中 | `████▓░░░░░ 3/7 ｜ 🟥 2.3 組み立てる: 鍵が無い` |
| 完了 | `██████████ 7/7 ｜ ✅ 完了 47分（見込み 43分）` |
| 狭い幅 | `3/7 ｜ 約26分（15:12）` |
| 作業なし | 何も出さない |

- 幅が足りないときは、手順の経過 → 手順名 → バーの順に削る。**残り全体の時間は最後まで残す。**
- 「指示待ち」は、計画が終わっていないのに Claude の応答が終わったとき（§8.4 の Stop フック）。
  待っても進まないので、終了予定の時刻は出さず「再開後 残り約 n分」とする。

### 4.2 詳しい表示（`baro` / 区切りの報告）

区切り = 段階が終わったとき・回答待ちになったとき・停止したとき・完了したとき。
返信に貼るときはコードブロックに入れる（桁を揃えるため）。

```
📋 採用ページ 5 社の画像差し替え
   ⏳ 残り約 26分（終了予定 15:12） ・ 🕒 18分 / 全体 44分
   ████▓░░░░░ 41% ・ 手順 3/7
│                                     経過/見込み
├─ 1 調べる                            6/ 5分 █████
│   ├─ 🟩 1.1 公開中のページを確認     2/ 2分
│   └─ 🟩 1.2 画像の候補を集める       4/ 3分 🔺+1分
├─ 2 作る                             12/28分 ██▓░░
│   ├─ 🟩 2.1 差し替える画像を決める   5/ 5分
│   ├─ 🟨 2.2 設計書を書く             7/10分 ◀ 作業中
│   └─ ⬜ 2.3 組み立てる               -/13分
└─ 3 仕上げ                            -/10分 ░░░░░
    ├─ ⬜ 3.1 スマホ幅で確かめる       -/ 5分
    └─ ⬜ 3.2 公開する                 -/ 5分
```

- 入れ子は 2 段（段階 › 手順）が基本、深くても 3 段まで。番号（`2.2`）はコマンドで手順を指すのに使う。
- 木の「見込み」は Claude が付けた生の値。残り時間・終わる時刻だけが補正後の値。補正の倍率は画面に出さない（利用者が知りたいのは残り時間と終わる時刻だけ）。倍率は `baro calibrate` / `baro stats` で見る。
- 手順を追加した・見込みを変更したときは、2 行目の下に理由を出す。

```
   ⏳ 残り約 34分（終了予定 15:20） ・ 全体 52分（+8分: 2.3 画像が 3 枚多かった）
```

```
   ✅ 完了 ・ 🕒 47分（当初の見込み 43分 🔺+4分）
   見込みどおり 5/7 手順 ・ 最も延びた: 2.3 組み立てる +5分
```

## 5. 時間の数え方

| 値 | 決め方 |
|---|---|
| 見込み | 計画時に Claude が手順ごとに分で付ける。1 手順は 2〜20 分（それより大きければ分ける） |
| 経過 | 手順の start〜done の実時間。回答待ち（🟦。`baro wait` と、Claude が AskUserQuestion で聞いている間）と指示待ちの間は数えない |
| 補正の倍率 r | 手順ごとに、テーマ（手順の種類）と計画の中の実績で決める（下の「補正」）。0.05〜3.0 に収める |
| 残り | 作業中の手順の max(見込み×r − 経過, 1分) ＋ まだの手順の 見込み×r の合計（⬛ は除く。r は手順ごと） |
| 終わる時刻 | いまの時刻 ＋ 残り（5 分単位に丸めない。分まで出す） |
| 全体 | 経過の合計 ＋ 残り |
| 進み具合 % | 経過 ÷ 全体 |

- 作業中の手順が見込みの 1.5 倍を超えたら、Claude は `baro est` で見込みを直し、理由を出す。
- 当初の見込み（plan 時点の合計）は別に持ち、完了時に比べる。
- 補正の元データは完了した手順の (見込み, 実績) の組（`history.jsonl`）。

#### 補正

手順の名前を **テーマ**（調べる・作る・テスト・文書・git/PR・人の確認 など）に分け、テーマごとに倍率を持つ。
見込みに対する実績の比は仕事の種類で大きく違う（2026-10-20 時点の記録で、git・PR は 0.08 倍、人の確認は 1.19 倍）。

倍率はどの段も **実績÷見込みの幾何平均**（log の平均）で、仮の手順 W 件ぶんの上の段の値と混ぜる。
手順 i の比を q_i = 実績_i ÷ 見込み_i、L = log とすると:

1. 履歴の倍率 r_h = exp((Σ L(q_i) + L(1.0) × W_h) ÷ (n + W_h))。直近 100 手順。
2. テーマの倍率 r_t = exp((Σ L(q_i) + L(r_h) × W_t) ÷ (n_t + W_t))。そのテーマの直近 100 手順。記録の無いテーマは r_h。
3. 計画の倍率 f = exp(Σ L(実績_i ÷ (見込み_i × r_t)) ÷ (n_p + W_p))。Σ はこの計画で終わった手順。
4. 手順の倍率 r = r_t × f。r_h・r_t・r は 0.05〜3.0 に収める。

- W は「仮の手順を何件ぶん混ぜるか」の重み。記録が少ないうちは上の段の値に寄る。既定は W_h 5・W_t 5・W_p 5。
- テーマを使わない（r_t = r_h）とき、手順の倍率は旧来の 2 段（履歴 → 計画）の式と同じ値になる。
- 計算は毎回、その場の `history.jsonl` で行う（スキルを使わなくても、記録が増えるほど当たる）。
- 2026-10-28 までは合計の比（Σ実績 ÷ Σ見込み）だった。人の返事や機械の処理を待って見込みの何倍にも延びた少数の手順
  （131 分の保守・44 分の待ちなど）が合計を押し上げ、この PC の記録では合計の比 0.21 が中央値 0.115 の 2 倍になっていた。
  ずれの指標 |L(予測/実績)| の平均を最小にするのは log の平均なので、幾何平均に変えた（下の表）。

##### テーマ分けと calibration.json

- テーマ分けはキーワードで行う。先頭のテーマから順に見て、手順の名前にキーワードを 1 つでも含む最初のテーマにする（どれにも入らなければ `other`）。
  組み込みの分け方は `calib.DEFAULT_THEMES`（人の確認 → git・PR・デプロイ → テスト → 文書 → 調べる → 作る の順）。
- `~/.claude/baro/calibration.json` に、使うテーマ分け（`themes`）・重み（`weights`）・テーマで分けるか（`mode`: theme / global）と、
  分析用の特徴データ（`features`: テーマごとの手順数・見込みと実績の合計・比の中央値と 25〜75%・掛ける倍率・例）、
  過去の記録で比べた結果（`backtest`）を置く。無ければ組み込みの値を使う。
- 無ければ、最初に補正を計算するとき（最初の表示）にその PC の履歴で作る。`baro calibrate` が作り直し、`baro end` のたびにも自動で作り直す（テーマ分けは保つ）。PC ごとのファイルなのでリポジトリには入れない。
  - 過去の手順を 1 つずつ、それより前の記録だけで予測し、ずれ（|log(予測/実績)| の平均を倍に直した値）を
    補正なし・全体の補正だけ・テーマ別で比べる。テーマ別が全体の補正だけより悪ければ `mode` を global にする。
  - 記録が 20 手順以上あれば、重みを 5・10・20・40 の組から選ぶ（既定の重みよりずれが 3% 以上小さいときだけ変える）。
- テーマ分けのキーワードを直すのは `/baro-calibration` スキル（`baro setup --apply` で入る。スキルだけなら `baro skill --install`。`--undo` で消える）。候補を `--dry-run` で比べ、
  ずれが小さくなるときだけ採用する。

- 2026-10-28 時点の記録（620 手順・186 計画。直近 300 手順で比べる）:

  | 方式 | ずれ（倍） | 1.5 倍以内 |
  |---|---|---|
  | 補正なし | 9.35 | 4% |
  | 合計の比（旧。履歴 20・テーマ 10・計画 10 分） | 2.61 | 26% |
  | 幾何平均（履歴 5・テーマ 5・計画 5 件） | 2.33 | 28〜31% |

  実績÷見込みは見込みの大きさ（3 分でも 20 分でも 0.11〜0.12 倍）にも時期にもほとんどよらず、残るずれは手順ごとのばらつき
  （25〜75% で 0.06〜0.23 倍）。これ以上は名前（テーマ）以外の手がかりが要る。

- 2026-10-20 時点の記録（39 手順・8 計画）で比べたずれ:

  | 方式 | ずれ（倍） |
  |---|---|
  | 補正なし | 9.9 |
  | 全体の補正だけ（旧来の 2 段・既定の重み） | 2.60 |
  | テーマ別（既定の重み） | 2.48 |
  | 全体の補正だけ（選んだ重み 履歴 5・テーマ 40・計画 5） | 2.21 |
  | テーマ別（選んだ重み） | 2.20 |

  いまの記録はほとんどのテーマが見込みの 0.1 倍前後で、テーマで分ける効きはまだ小さい（人の確認だけが大きく違う）。
  記録が増えたら同じ比べ方（`baro calibrate`）でやり直す。

- それ以前の比べ（12 手順・4 計画）: 旧方式（10 手順たまるまで 1.0・0.7〜2.0）8.9 → 履歴を 1.0 に寄せる・0.1〜3.0 で 4.9 → ＋計画の倍率で 3.5。
  実績は見込みの 0.04〜0.23 倍で、0.7 の下限が効いて旧方式は補正できていなかった。

## 6. コマンド

### 6.1 Claude が呼ぶもの

```
baro plan "採用ページ 5 社の画像差し替え" <<'EOF'
調べる
  公開中のページを確認    2
  画像の候補を集める      3
作る
  差し替える画像を決める  5
  設計書を書く           10
  組み立てる             13
仕上げ
  スマホ幅で確かめる      5
  公開する                5
EOF

baro start 2.2
baro done 2.2 [-m "メモ"]
baro est 2.3 20 -r "画像が 3 枚多かった"     # 見込みを直す（理由は必須）
baro add 2 "権利確認" 5 --after 2.2 -r "理由"  # 段階 2 に手順を足す（番号は 2.4。top で最上位）
baro wait 3.2 "公開してよいか"               # 🟦 回答待ち（計測を止め、次の start / done で再開）
baro block 2.3 "鍵が無い"                    # 🟥 停止中
baro skip 3.1 -r "不要になった"              # ⬛ 中止（全体から外す）
baro show [--line]                          # 詳しい表示 / 1 行
baro end
```

- plan の入力は字下げ（2 文字）で入れ子を表し、行末の数字を見込み（分）とする。数字の無い行は段階。
- `start` を呼ばずに `done` したときは、前の区切り（直前の done・計画の作成・再開）から今までをその手順の時間とみなす。
- `start` は前の 🟨 を自動で終わらせない。🟨 が 2 つになったら警告を出す（done し忘れに気づけるよう）。
- どのコマンドも、実行後に 1 行表示を標準出力に出す（Claude がそのまま返信の先頭に使える）。

### 6.2 人が打つもの

```
baro           # いまのセッションの詳しい表示（セッションが 1 つなら自動で選ぶ）
baro ls        # 進行中の計画があるセッションの一覧
baro stats     # 見込みの当たり具合（補正の倍率と、延びやすい手順）
baro calibrate [--dry-run] [--list] [--json] [--themes FILE] [--reset]   # テーマごとの特徴データを作り、補正の設定を決める
baro skill [--install] [--remove]   # キャリブレーションのスキル（/baro-calibration）を出す・入れる
baro doctor    # 設定の確認（ステータスライン・フックが baro になっているか）
baro setup [--apply] [--undo]   # Claude Code の設定に baro を組み込む / 外す（--apply が無ければ変更点の表示のみ）
```

## 7. 表示のルール

- **右の縦線は使わない。** 日本語・絵文字の幅のずれで崩れるため、罫線は左の枝（`├─ │ └─`）だけ。
- 桁揃えは表示幅で測る（`unicodedata.east_asian_width` が W/F = 2、絵文字は固定の表で 2、ほかは 1）。
- 幅が端末によって揺れる記号（`▶️` `⚠️` `⏱️` など、異体字セレクタ付きのもの）は使わない。
  使う絵文字は 🟩🟨⬜🟦🟥⬛ 📋 🕒 ⏳ 💤 🔺 🙋 ✅ ◀ に限る（手順の行の印と見出し）。
- バーは █▓░ で描く（幅 1 で数える）。絵文字のマスより細かく、Desktop の帯でもきれいに見えるため。
  East Asian Width が A（あいまい）なので、あいまい幅を 2 で描く設定の端末では幅がずれる。
- ステータスラインのバーには端末の色（ANSI）を付ける: █ は緑、▓ は状態の色（作業中 黄・回答待ち 青・停止中 赤）、░ は灰。
  幅の計算では色の指定を数えない。返信に貼る `baro show --line` には色を付けない。
- 文言はふつうの日本語にする（「回答待ち」「停止中」「中止」「終了予定」など定番の言い回し。説明口調の言い換えを画面に出さない）。

## 8. 仕組み

### 8.1 全体

```
Claude（Bash）──baro plan / start / done …──▶ ~/.claude/baro/sessions/<session_id>.json
                                                   ▲            │ 完了した手順
Claude Code ──statusLine──▶ baro statusline ──読む─┤            ▼
            ──Stop / UserPromptSubmit──▶ baro hook ┘      ~/.claude/baro/history.jsonl（補正用）
baro calibrate / baro end ──history.jsonl から──▶ ~/.claude/baro/calibration.json（テーマ分け・重み・特徴データ）
Desktop の Code タブ ──mod baro-band──▶ baro statusline --no-chain ──読む─┘
人 ──▶ baro / baro ls / baro stats ──読む──┘
```

### 8.2 実装

- **Python 3.9 以上・標準ライブラリだけ。** 外部の依存を持たない（どの Python でも動くように）。
- 置き方:

```
baro/
├─ pyproject.toml          # [project.scripts] baro = "baro.cli:main"
├─ src/baro/
│   ├─ cli.py              # 引数の解析と各コマンド
│   ├─ store.py            # 保存ファイルの読み書き（排他・書き換えは一時ファイル → rename）
│   ├─ clock.py            # 経過・残り・補正・終わる時刻の計算（時刻を引数で受け、テストしやすく）
│   ├─ calib.py            # テーマ分け・特徴データ・過去の記録での比べ・重みの選び（calibration.json）
│   ├─ skills/baro-calibration/SKILL.md   # /baro-calibration スキル（baro skill --install で入る）
│   ├─ render.py           # 1 行 / 詳しい表示 / 一覧（表示幅の計算もここ）
│   └─ hooks.py            # statusline と Stop / UserPromptSubmit の受け口
├─ mod/baro-band/          # Desktop の Code タブの帯（Claude Code の mod・TypeScript）
│   ├─ hooks/register.tsx
│   └─ tests/band.test.tsx # claude plugin test で流す
└─ tests/                  # clock と render を中心に
```

- 入れ方: `uv tool install git+https://github.com/akkijp/baro`（開発中は clone して `uv tool install -e .`）で `~/.local/bin/baro` に置く。

### 8.3 セッションの見分け方

- Claude の Bash には `CLAUDE_CODE_SESSION_ID` が入っている（2.1.304 で確認済み）。`baro` はこれを使う。
- ステータスラインとフックは、stdin の JSON の `session_id` を使う。
- `CLAUDE_CODE_SESSION_ID` が会話の記録（`~/.claude/projects/<dir>/<session_id>.jsonl`）の名前と一致することは確認済み。
  `/clear` のあとに値が変わるかはまだ確かめていない
  （変わるなら、古いセッションの計画は `baro ls` に「更新なし」として残し、24 時間で一覧から外す）。
- 人が打つ `baro` は環境変数が無いので、進行中のセッションが 1 つならそれ、複数なら一覧を出す。

### 8.4 フック

| フック | baro がすること |
|---|---|
| statusLine | stdin を Orca の送信スクリプトにそのまま渡してから、1 行表示を出す（§8.5） |
| Stop | 計画が終わっていなければ「指示待ち」にして計測を止める |
| UserPromptSubmit | 止めていた計測を再開する。計画があれば、いまの 1 行を Claude への追加の文脈として渡す（compact 後も更新し忘れないように） |

回答待ち（`baro wait`）と指示待ちは別の状態として持つ。どちらも経過には数えない。

- バックグラウンドの作業の完了や mod の読み込みの知らせも、UserPromptSubmit として届く
  （`prompt` が `<task-notification>` で始まる。2.1.304 で確認）。人の返事ではないので、**回答待ちは解かない**。
  指示待ちは解く（知らせを受けて Claude が作業を続けるため。終われば Stop でまた止まる）。

### 8.5 ステータスラインと Orca の共存

- いまの statusLine は Orca の送信スクリプト（`~/.orca/agent-hooks/claude-statusline.sh`）で、画面には何も出していない。
- statusLine の command を `baro statusline` に替え、baro が受けた stdin をそのまま Orca のスクリプトへ渡す
  （1 秒で打ち切る・失敗しても無視）。そのあとで 1 行表示を出す。
- 元の command は `~/.claude/baro/config.json` に保存し、`baro doctor` で「Orca の更新で statusLine が戻されていないか」を確認する。
- ステータスラインは Claude Code が呼んだときに描き直される。作業中は頻繁に呼ばれるが、
  何も起きていない間に「終わる時刻」がずれて見えないかを実装時に確かめる（必要なら `refreshInterval` の有無を調べる）。

### 8.5.1 Claude Desktop の Code タブ（mod baro-band）

- Desktop の Code タブにはステータスラインが出ない（2026-10-20 時点）。代わりに Claude Code の mod で、
  入力欄の上の帯（`ui.render` の `AbovePrompt`）に同じ 1 行を描く。帯はターミナル・Desktop の両方で描かれるが、
  ターミナルではステータスラインと重なるので描かない（`e.surface === 'terminal'` なら素通し）。
- mod は `baro statusline --no-chain --width <帯の幅>` を `$.process.run` で呼び、stdin に `{"session_id": …}` を渡す。
  計画と計測は baro のまま（mod は表示だけ）。`--no-chain` は元の statusLine（Orca）へ渡さないため。
- 出力の ANSI の色は、帯では Text の色に置き換える（32 → success・33 → warning・34 → suggestion・31 → error・90 → dimColor）。
- 1 行目の末尾に「詳細」ボタンを置き、押すとペイン（`ui.open`・id `baro-detail`）に `baro --session <id> show` の木を出す（2026-10-20 改訂 4）。
- 2 行目に使用量を出す: `$.session.usage()` の rateLimits（five_hour・seven_day）・context.percent・cost.usd と、`$.agent.list()` の実行中のサブエージェント数。
  80% 以上で warning・95% 以上で error の色。使用量の行はターミナルでも描く（計画の行だけステータスラインと重なるので描かない）。
- 描き直し: `tool.call`（baro start / done は Bash から呼ばれる）・`prompt.submit`・`turn.complete` のあとと、30 秒ごと。帯の幅が変わったときも。
- 読み込ませ方: `~/.claude/settings.json` の `env` の `CLAUDE_CODE_PLUGIN_DIRS` に `mod/baro-band` の絶対パスを書く。
  Desktop が起動するセッションも、ターミナルのセッションもこれを読む。uv / pipx で入れた baro には mod が含まれないので、clone が要る。
- `baro` は PATH に `~/.local/bin` を足して探す（Desktop から起動されたセッションの PATH には入っていないことがあるため）。
- Desktop で Stop / UserPromptSubmit のフックが動くかは未確認（2026-10-20 時点の Desktop の会話記録にはフックが動いた跡が無かった）。
  動かない場合、指示待ちの間も計測が止まらない。確かめて、必要なら mod の `turn.complete` / `prompt.submit` から `baro hook` を呼ぶ。

### 8.6 Claude へのルール

グローバルの CLAUDE.md に次を書く。

- 3 手順以上になりそうな依頼では、最初に `baro plan`（見込みは手順ごとに分で）。
- 手順を始めるとき `baro start`、終えたら `baro done`。回答を求めるときは `baro wait`。
- 返信の先頭に `baro show --line` の 1 行。区切りでは `baro show` をコードブロックで。
- 見込みの 1.5 倍を超えたら `baro est` で直し、理由を言う。

### 8.7 保存ファイル

```json
{
  "session_id": "…",
  "title": "採用ページ 5 社の画像差し替え",
  "cwd": "/home/you/projects/site",
  "created": "2026-10-20T14:30:00+09:00",
  "planned_total_min": 43,
  "paused": null,
  "items": [
    { "id": "1", "name": "調べる", "children": [
      { "id": "1.1", "name": "公開中のページを確認", "est_min": 2, "state": "done",
        "spans": [["2026-10-20T14:30:10+09:00", "2026-10-20T14:32:05+09:00"]] }
    ]}
  ],
  "events": [
    { "at": "2026-10-20T14:41:00+09:00", "kind": "est", "id": "2.3", "from": 13, "to": 20,
      "reason": "画像が 3 枚多かった" }
  ]
}
```

- `spans` は作業していた区間の並び。回答待ち・指示待ちで区切る。経過はこの合計。
- `paused` は `null` / `{"kind": "wait", "id": "3.2", "question": "…"}` / `{"kind": "stopped"}`。
